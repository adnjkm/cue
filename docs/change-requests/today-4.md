1. **Need**: `components/ui/toast.tsx` to send focus back to where it came from when a toast closes from inside it (Escape, the close button, an action), as Base UI already does for toasts entered with F6.
2. **Why**: Base UI records the previous focus only on F6, so a keyboard user who Tabs into a toast and presses Escape lands on the page body. Today's "Moved to 11:45am." toast did this (measured on f2dd3f2: after Escape `document.activeElement` was `BODY`), and Calendar's "Added 1 course" toast with Undo has the same path.
3. **Proposed diff**: a module-level `let cameFrom: HTMLElement | null = null`; `ToastViewport` passes `onFocus={(e) => { if (e.relatedTarget instanceof HTMLElement && !e.currentTarget.contains(e.relatedTarget)) cameFrom = e.relatedTarget; onFocus?.(e) }}`; and the exported manager becomes `const manager = ToastPrimitive.createToastManager(); const toast: typeof manager = { ...manager, add: (o) => manager.add({ ...o, onClose: () => { o.onClose?.(); const closing = document.activeElement?.closest('[data-slot="toast"]'); if (closing) queueMicrotask(() => { if (closing.contains(document.activeElement) && cameFrom?.isConnected) cameFrom.focus() }) } }) }` (the manager's methods are closures, so spreading it is safe). The microtask lets a feature's own `onClose` and Base UI's move to the next stacked toast win.
4. **Workaround in use**: `features/today/TodayPage.tsx` passes `onClose: returnFocusTo(target)` on each of its four toasts, the same check sending focus to the moved row (or the h1 when the block left today); the walkthrough step reaches Undo by Tab and asserts focus on the 11:45am row after Escape.
5. **Unblocks**: the same keyboard path on every toast in the app, after which Today's `returnFocusTo` stays only to pick the moved row over the element focus came from.
